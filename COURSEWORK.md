# Парный курсовой проект: карта требований и защита

Версия приложения **1.2.0**. Исследование геометрии страниц «Юности» и локальный
OCR любого текста соединены в одном FastAPI-приложении. Жанровый фильтр не применяется.

## Где выполнены критерии

| Требование | Реализация, которую можно показать |
|---|---|
| Не менее пяти классов | `TextExtractor`, `TextPageResult` (`yunost/text.py`); `LayoutWord`, `LayoutBlock` (`yunost/layout.py`); `OcrEngine`, `TesseractEngine` (`yunost/ocr.py`); `CorpusRepository`, `CorpusFilter` (`yunost/storage.py`); `AnalyticsService` (`yunost/analytics.py`). Это рабочие объекты, не классы-заглушки. |
| Наследование | `TesseractEngine(OcrEngine)`: реализует абстрактный `read_lines()` и использует унаследованный `read_block()`; в актуальном OCR также предоставляет `read_layout()`. `TextPageResult(Sequence)` реализует стандартный интерфейс последовательности. |
| Композиция | `TextExtractor` содержит основной/повторный OCR-движки; `TextPageResult` содержит `LayoutBlock`, блок содержит `LayoutWord`; `AnalyticsService` содержит `CorpusRepository`. |
| Реальная запись и чтение БД | `CorpusRepository.import_csv()` записывает выпуски, страницы и признаки в SQLite транзакцией; `select()` выполняет SQL JOIN и параметризованный отбор. Сервис аналитики читает только результаты этих SQL-запросов. |
| Не менее трёх визуализаций с изменяемыми параметрами | `/analytics`: гистограмма (признак и интервалы), динамика (признак и среднее/медиана), рассеяние (признаки X/Y). Для всех — годы и тип источника, изменения без редактирования кода; доступны числовые таблицы. |
| Не менее трёх переопределений методов | `TextPageResult(Sequence)` явно переопределяет `__len__`, `__iter__`, `__getitem__` базового класса `collections.abc.Sequence`: Python-протокол контейнера принятых текстовых блоков. Используются **все три** в `server.page_response()`: счётчик, список блоков, первый блок. Дополнительно — переопределение `read_lines()` у OCR-движка; старый `TextBlock.__lt__` сохранён, но не служит основным обоснованием. |
| Декораторы | Собственный `@timed` с `functools.wraps` (`yunost/decorators.py`) измеряет время OCR и трёх аналитических методов; `@dataclass`, `@property`, `@abstractmethod`, маршруты `@app.get`/`@app.post`. |
| Вызываемый сервер (бонус) | FastAPI: `POST /api/ocr`, четыре `GET /api/analytics/*`, `/api/health`, автодокументация `/docs`; `run_app.py` запускает только на `127.0.0.1`. |

Спецметоды считают/перебирают/индексируют **только принятые** блоки; сомнительные
фрагменты остаются в `result.blocks`/`all_blocks`. Поддерживаются отрицательные индексы
и срезы, выход за границы даёт `IndexError`, первый блок пустого результата — `None`.
Это явные переопределения существующих методов базового `Sequence`, не автоматически
сгенерированные методы `dataclass`. Тест проверяет и наследование, и замену всех трёх методов.

## Схема БД и происхождение данных

```text
issues(id PK, year, month)
  └─ pages(file PK, issue_id FK, page, source; UNIQUE(issue_id, page))
       └─ features(page_file PK/FK, девять числовых признаков)
metadata(key PK, value)  — SHA256 двух импортированных CSV
```

111 страниц, 15 номеров, годы 1957/1962/1963/1965/1967; 75 сканов и 36 фото.
CSV сохранены как воспроизводимый источник; в базу не переносятся исходные пути
чужого компьютера. Первое обращение импортирует данные, последующие работают
без CSV. Повторный импорт делает upsert; весь пакет откатывается при ошибке.
Новые страницы добавляются, совпадающие обновляются, отсутствующие не удаляются.
Имена SQL-колонок допускаются только из списка метрик; значения фильтров передаются
параметрами SQL, не конкатенацией. Для каждого обращения открывается своё соединение.
Чужая БД и будущая версия схемы отклоняются без изменения содержимого.

Один пропуск `raggedness` хранится как SQL NULL и исключается только из графика,
которому нужен этот признак. Для пар используются только полные пары.
Годовая агрегация выполняется по страницам отдельно для сканов и фотографий;
также возвращаются числа страниц и номеров. Непредставленные годы не заполняются.
Интервалы гистограммы одинаковой ширины, правый край последнего включается.

**Ограничение интерпретации:** фотографии — отобранные преимущественно поэтические
страницы, не случайная выборка. Страницы одного выпуска не независимы. Графики
показывают свойства имеющегося корпуса, не доказывают причинность и не измеряют OCR.

## Сценарий защиты (5–7 минут)

1. Запустить по `START_HERE.md`. На `/` загрузить `examples/page_3.png`
   (в репозитории — `1967-12/page_3.png`), показать прозу/стихи без отбора,
   физические строки и выгрузку `.txt`; сверить с оригиналом.
2. Открыть `/analytics`: показать 111 страниц/15 номеров и три графика.
   Изменить признак и число интервалов 12→23; медиану→среднее; обе оси рассеяния.
   Выбрать только фото, затем годы 1958–1960 — корректная пустая выборка.
   Вернуть 1957–1967 и все источники. Раскрыть числовые таблицы.
3. В `yunost/storage.py` показать транзакционные `INSERT ... ON CONFLICT` и
   `SELECT ... JOIN ... WHERE`. Выполнить импорт **дважды** в демонстрационную БД:

   ```bash
   .venv-app/bin/python import_corpus.py --database data/demo.sqlite3
   .venv-app/bin/python import_corpus.py --database data/demo.sqlite3
   .venv-app/bin/python -c "import sqlite3; d=sqlite3.connect('data/demo.sqlite3'); print(d.execute('SELECT COUNT(*) FROM pages').fetchone()); print(d.execute('SELECT COUNT(*) FROM features WHERE raggedness IS NULL').fetchone())"
   ```

   Результаты — `(111,)` и `(1,)`, не 222 и не 0. Демонстрационная база не заменяет рабочую.
4. Показать классы и связи из таблицы выше; отдельно `TextPageResult` и использование
   `len(result)`, `for b in result`, `result[0]` в сервере. Показать `@timed` и строки
   времени в логах при обновлении графика.
5. Открыть `/docs` и выполнить запрос графика с изменёнными параметрами.
   Отправить `bins=1` — ответ 422. Подчеркнуть, что сервер доступен только локально.
6. В полном репозитории запустить тесты:

   ```bash
   TESSDATA_PREFIX="$PWD/tessdata" .venv/bin/python -m pytest tests/ -q
   ```

   Тестовые библиотеки устанавливаются через `requirements.txt`; маленький архив
   приложения содержит runtime, данные и документацию, но не весь исследовательский
   репозиторий и набор тестов. Проверки БД/аналитики — `tests/test_analytics.py`.

## Что не менялось

Алгоритм OCR версии 1.1.0, веса и исторические CSV/ноутбук сохранены. Новый контракт
OCR отличается только добавочным полем `first_block`; прежние поля сохранены.
`RELIABILITY.md` — **историческая проверка OCR 1.1.0**, не отчёт о новых графиках.
Проверка расширения 1.2.0 — отдельный `COURSEWORK_CHECK.md`. Загрузки OCR не сохраняются
в исследовательскую БД. Chart.js включён локально с лицензией MIT.
