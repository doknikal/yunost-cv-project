# Парный курсовой проект: критерии и сценарий защиты

Версия приложения **1.3.0**. FastAPI-приложение объединяет анализ верстки страниц «Юности» и локальный OCR любого текста.
Жанровый фильтр не применяется.

## Где выполнены критерии

| Требование | Где смотреть |
|---|---|
| Не менее пяти классов | `TextExtractor`, `TextPageResult` (`yunost/text.py`); `LayoutWord`, `LayoutBlock` (`yunost/layout.py`); `OcrEngine`, `TesseractEngine` (`yunost/ocr.py`); `CorpusRepository`, `CorpusFilter` (`yunost/storage.py`); `AnalyticsService` (`yunost/analytics.py`). Все классы рабочие, заглушек нет. |
| Наследование | `TesseractEngine(OcrEngine)` реализует абстрактный `read_lines()` и использует унаследованный `read_block()`. Для актуального OCR добавлен `read_layout()`. `TextPageResult(Sequence)` реализует стандартный интерфейс последовательности. |
| Композиция | `TextExtractor` содержит основной и повторный OCR-движки. `TextPageResult` содержит `LayoutBlock`, блок содержит `LayoutWord`. `AnalyticsService` содержит `CorpusRepository`. |
| Запись и чтение БД | `CorpusRepository.import_csv()` одной транзакцией записывает выпуски, страницы и признаки в SQLite. `select()` выполняет SQL JOIN с параметризованным отбором. Сервис аналитики читает только результаты этих запросов. |
| Три визуализации с параметрами | `/analytics`: гистограмма (признак и число интервалов), динамика (признак и среднее или медиана), рассеяние (признаки X и Y). У всех есть фильтры по годам и источнику, у каждого графика числовая таблица. Параметры меняются без правки кода. |
| Три переопределенных метода | `TextPageResult(Sequence)` переопределяет `__len__`, `__iter__`, `__getitem__` базового класса `collections.abc.Sequence`. Сервер использует все три в `server.page_response()`: счетчик, список блоков, первый блок. Дополнительно `TesseractEngine` переопределяет `read_lines()`, а `TextBlock.__lt__` остался от старой версии. |
| Декораторы | Собственный `@timed` с `functools.wraps` (`yunost/decorators.py`) замеряет время OCR и трех методов аналитики. Также `@dataclass`, `@property`, `@abstractmethod`, маршруты `@app.get` и `@app.post`. |
| Сервер (бонус) | FastAPI: `POST /api/ocr`, четыре `GET /api/analytics/*`, `/api/health`, документация `/docs`. `run_app.py` слушает только `127.0.0.1`. |

Специальные методы считают, перебирают и индексируют **только принятые** блоки. Сомнительные фрагменты остаются
в `result.blocks` и `all_blocks`. Работают отрицательные индексы и срезы, выход за границы дает `IndexError`,
первый блок пустого результата равен `None`. Это явные переопределения методов `Sequence`, а не методы,
сгенерированные `dataclass`. Тест проверяет и наследование, и замену всех трех методов.

## Схема БД и данные

```text
issues(id PK, year, month)
  └─ pages(file PK, issue_id FK, page, source; UNIQUE(issue_id, page))
       └─ features(page_file PK/FK, девять числовых признаков)
metadata(key PK, value)  — SHA256 двух импортированных CSV
```

111 страниц, 15 номеров (1957, 1962, 1963, 1965, 1967), 75 сканов и 36 фото.
CSV остаются воспроизводимым источником. Пути с чужого компьютера в базу не переносятся.
Первое обращение к аналитике импортирует данные, следующие работают без CSV.
Повторный импорт обновляет совпавшие страницы, добавляет новые и не удаляет отсутствующие.
При ошибке откатывается весь пакет.

Имена SQL-колонок принимаются только из списка метрик, значения фильтров передаются параметрами, а не конкатенацией.
Каждое обращение открывает свое соединение. Чужая БД и более новая версия схемы отклоняются без изменений.

Единственный пропуск `raggedness` хранится как SQL NULL и исключается только из графика, которому нужен этот признак.
Для пар берутся только полные пары. Годовая агрегация считается отдельно для сканов и фото; в ответе есть число страниц и номеров.
Годы без данных не заполняются. Интервалы гистограммы одинаковой ширины, правый край последнего включен.

**Как читать графики.** Фото 1962–1965 — подборка в основном стихотворных страниц, а не случайная выборка.
Страницы одного номера зависимы. Графики описывают имеющийся корпус: причинность они не доказывают, качество OCR не измеряют.

## Сценарий защиты (5–7 минут)

1. Запустить по `START_HERE.md`. На `/` загрузить `1967-12/page_3.png`. Показать прозу и стихи без отбора,
   физические строки, выгрузку `.txt`, сверить с оригиналом. Включить правые края строк, открыть диагностику OCR/CV.
   Пояснить: геометрия не определяет жанр, не улучшает чтение слов и не заменяет старую метрику графиков.
2. Открыть `/analytics`: 111 страниц, 15 номеров, три графика. Поменять признак и число интервалов (12 → 23),
   медиану на среднее, обе оси рассеяния. Выбрать только фото, затем годы 1958–1960: выборка пустая, это корректно.
   Вернуть 1957–1967 и все источники. Открыть числовые таблицы.
3. В `yunost/storage.py` показать транзакционный `INSERT ... ON CONFLICT` и `SELECT ... JOIN ... WHERE`.
   Выполнить импорт **дважды** в демонстрационную БД:

   ```bash
   .venv-app/bin/python import_corpus.py --database data/demo.sqlite3
   .venv-app/bin/python import_corpus.py --database data/demo.sqlite3
   .venv-app/bin/python -c "import sqlite3; d=sqlite3.connect('data/demo.sqlite3'); print(d.execute('SELECT COUNT(*) FROM pages').fetchone()); print(d.execute('SELECT COUNT(*) FROM features WHERE raggedness IS NULL').fetchone())"
   ```

   Ожидаемый вывод: `(111,)` и `(1,)`, не 222 и не 0. Рабочую базу демонстрационная не заменяет.
4. Показать классы и связи из таблицы выше. Отдельно показать `TextPageResult` и как сервер использует
   `len(result)`, `for b in result`, `result[0]`. Показать `@timed` и строки времени в логах при обновлении графика.
5. Открыть `/docs`, выполнить запрос графика с другими параметрами. Отправить `bins=1`: ответ 422.
   Сказать, что сервер доступен только локально.
6. Запустить тесты (нужны `pytest` и `httpx`, в `requirements-app.txt` их нет):

   ```bash
   .venv-app/bin/pip install pytest httpx
   TESSDATA_PREFIX="$PWD/tessdata" .venv-app/bin/python -m pytest tests/ -q
   ```

   Проверки БД и аналитики лежат в `tests/test_analytics.py`. Компактный архив приложения тестов не содержит.

## Что не менялось

Алгоритм OCR версии 1.1.0, веса и исторические CSV остались прежними. Ответ OCR получил поля `first_block` (1.2.0)
и `edge_analysis` (1.3.0), остальные поля сохранены. Загрузки OCR в исследовательскую БД не пишутся.
Chart.js лежит в репозитории (лицензия MIT).

`RELIABILITY.md` проверяет OCR версии 1.1.0, а не графики. Расширение 1.2.0 описано в `COURSEWORK_CHECK.md`.
Новый метод краев строк и его проверка — в `EDGE_METHOD.md`.
