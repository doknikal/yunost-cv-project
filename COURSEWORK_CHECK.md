# Проверка расширения 1.2.0, 21 октября 2026

Документ дополняет отчет об OCR версии 1.1.0 и не заменяет его.

## Автоматические проверки

Команда: `TESSDATA_PREFIX="$PWD/tessdata" .venv/bin/python -m pytest tests/ -q`.
Результат: **161 passed**, без предупреждений. Из них 111 прежних тестов и 50 новых (`tests/test_analytics.py`, `tests/test_app_bundle.py`).
Среда: Python 3.9, macOS, Tesseract 5.5.3.

Новые тесты проверяют:
- точное совпадение всех девяти признаков и метаданных в CSV и SQLite;
- 111 страниц, 15 номеров, 75 сканов, 36 фото, один SQL NULL;
- повторный импорт, обновление значений, повторное открытие БД;
- чтение трех графиков при закрытом доступе к CSV;
- отказ при дубликатах, разных наборах страниц, несогласованных метаданных, дробном счетчике,
  отрицательных, NaN, Infinity и нечисловых значениях, недостающем столбце;
- полный откат транзакции, если в конце импорта падает SQL;
- чужие БД и неизвестная версия схемы остаются без изменений байтов;
- первое открытие БД в 12 обращений из шести потоков не создает дублей;
- список допустимых SQL-идентификаторов, границы лет и источники;
- суммы гистограмм, среднее и медиана по годам и источникам, полные пары для каждого признака;
- HTTP 200, 422, 503, локальные ресурсы, пустые выборки, независимость OCR от ошибки БД;
- три специальных метода, срезы, отрицательные индексы, `IndexError` и их использование в ответе OCR;
- состав и воспроизводимость ZIP: ресурсы аналитики, CSV и лицензия включены, локальная SQLite и кэши нет,
  SHA256-манифест верен, у `.command` режим 0755.

## Регрессия OCR на странице пользователя

Реальный `POST /api/ocr` для `1967-12/page_3.png` сравнили с сохраненным ответом версии 1.1.0
(`.venv/evaluation/reliability/final_user_page.json`). **Все прежние поля JSON совпали точно**:
текст, блоки, строки, слова, диагностика, разметка и PNG-overlay. Добавлено только поле `first_block`.
Результат: 14 принятых блоков, 3 547 символов, 209 физических строк. Алгоритм не менялся.
Полный прогон OCR по 111 страницам заново не делали. Прежние результаты описаны в `docs/ocr_evaluation/RELIABILITY.md`.

## Проверка в браузере

На работающем сервере открыли `/analytics`:
- три Chart.js canvas и таблицы: 12 интервалов, пять точек динамики, 110 полных пар, 111 выбранных страниц, один пропуск;
- «только фото», признак «число строк», 23 интервала: 36 страниц, сумма частот 36;
- среднее вместо медианы; обе оси рассеяния заменены на плотность чернил и текста: 36 полных пар;
- годы 1958–1960: все графики пусты, старые таблицы очищены;
- обратный диапазон 2000–1900: понятная ошибка, старых графиков нет;
- ответ на 2 интервала искусственно задержали до прихода ответа на 60 интервалов: остался новый график и 60 строк таблицы;
- имитация HTTP 503: вместо устаревшего графика показана ошибка, после восстановления сервера график строится снова;
- все ресурсы аналитики загружены с `127.0.0.1`, CDN нет.

Изображение трех отрисованных canvas выгрузили и просмотрели: оси, столбцы, серии и точки на месте.
Скриншот всего окна снять не удалось (`Screenshot needs a visible tab`), поэтому полную визуальную проверку страницы
и мобильных экранов мы не заявляем. Структуру и подписи проверили через accessibility snapshot. Linux и Windows не проверялись.

## Отдельная установка архива

ZIP 1.2.0 распаковали во временную папку с пробелами в пути, вне репозитория. Выполнили чистую установку
в собственную `.venv-app` и повторную установку. `pip check`: `No broken requirements found`.
Установщик сообщил только о новой версии pip, обновлять его не требовалось.
Системные Python и Tesseract в ZIP не входят, они уже были на машине.

Из этой папки запустили отдельный сервер на порту 8002: здоровье OCR `ok`, четыре API аналитики отвечают,
графики и таблицы строятся в браузере. OCR примера из архива совпал со всеми прежними полями эталона 1.1.0, включая overlay.
Явный CLI-импорт выполнили дважды: осталось 111 страниц. SQL дал одну NULL-ячейку `raggedness`, `PRAGMA foreign_key_check` вернул пустой список.
Новый независимый процесс прочитал три графика из готовой БД при несуществующих путях к CSV: повторный импорт для запросов не нужен.

Проверили SHA256 каждого файла из манифеста и совпадение с исходниками репозитория. Повторная сборка воспроизводима байт в байт.
Контрольная сумма ZIP лежит рядом: `dist/Yunost-OCR-1.2.0.zip.sha256`. У архива 1.1.0, старых корпусных JSON и русских весов хеши прежние.
В комплект 1.2.0 не входят датасет изображений и набор тестов: это компактный архив только для запуска.
