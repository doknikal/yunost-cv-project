# Проверка расширения 1.2.0 — 21 октября 2026

Это дополнение к историческому OCR-отчёту 1.1.0, а не его замена.

## Автоматические проверки

Команда: `TESSDATA_PREFIX="$PWD/tessdata" .venv/bin/python -m pytest tests/ -q`.
**161 passed**, без предупреждений в тестовом прогоне: прежние 111 тестов
и 50 новых (`tests/test_analytics.py`, `tests/test_app_bundle.py`).
Python 3.9, macOS, Tesseract 5.5.3.

Новые проверки покрывают:
- точное соответствие всех девяти числовых признаков и метаданных CSV↔SQLite;
- 111 страниц, 15 номеров, 75 сканов/36 фото, единственный SQL NULL;
- повторный импорт, обновление значений и повторное открытие БД;
- чтение всех трёх графиков после запрета доступа к CSV;
- отказ на дубликатах, разных наборах страниц, несогласованных метаданных,
  дробном счётчике, отрицательных/NaN/Infinity/нечисловых значениях, недостающем столбце;
- полный откат транзакции при ошибке SQL в конце импорта;
- сохранение чужих БД и неизвестной версии схемы без изменения байтов;
- конкурентное первое открытие (12 обращений, шесть потоков), без дублирования;
- allowlist SQL-идентификаторов, границы лет и источники;
- суммы гистограмм, среднее/медиану по годам/источникам, полные пары для каждого признака;
- HTTP 200/422/503, локальные ресурсы, пустые выборки, независимость OCR от ошибки БД;
- все три спецметода, срезы/отрицательные индексы/IndexError и их использование в OCR-ответе.
- комплектность и воспроизводимость ZIP: аналитические ресурсы/CSV/лицензия включены,
  локальная SQLite и кэши исключены, SHA256-манифест верен, `.command` имеют режим 0755.

Реальный `POST /api/ocr` для `1967-12/page_3.png` сравнили с сохранённым
`.venv/evaluation/reliability/final_user_page.json` версии 1.1.0:
**все прежние поля JSON совпали точно**, включая текст, блоки/строки/слова,
диагностику, разметку и PNG-overlay. Добавлен только `first_block`.
14 принятых блоков, 3 547 символов, 209 физических строк. Алгоритм не менялся.
Новый полный 111-страничный прогон OCR не выполнялся: его исторические результаты
описаны отдельно в `RELIABILITY.md` (в репозитории — `docs/ocr_evaluation/RELIABILITY.md`).

## Проверка браузера

На работающем сервере `/analytics`:
- три настоящих Chart.js canvas и таблицы: 12 интервалов, пять точек динамики,
  110 полных пар, выбранных страниц 111, пропуск одна страница;
- выбор «только фотографии», признака числа строк и 23 интервалов:
  36 страниц и сумма частот 36; среднее вместо медианы; замена обеих осей
  на плотность чернил/текста — 36 полных пар;
- диапазон 1958–1960 — все графики корректно пустые, старые таблицы очищены;
- обратный диапазон 2000–1900 — понятная ошибка и отсутствие старых графиков;
- искусственная задержка старого ответа (2 интервала) до завершения нового
  (60 интервалов): остался новый график и 60 строк таблицы;
- имитация HTTP 503: ошибка вместо устаревшего графика, после восстановления
  сервера график снова строится;
- все фактические ресурсы аналитики загружены с `127.0.0.1`, без CDN.

Изображение трёх реально отрисованных canvas выгружено и просмотрено: оси,
столбцы, серии и точки отображаются. Полный скриншот окна инструмент не смог
снять (`Screenshot needs a visible tab`); это не заявляется как полная визуальная
проверка страницы или мобильных устройств. Структура и подписи также проверены
через accessibility snapshot. Linux/Windows здесь не проверялись.

## Отдельная установка архива

ZIP 1.2.0 распакован в отдельную временную папку с пробелами в пути, вне репозитория.
Проведена свежая установка в собственную `.venv-app` и повторная установка:
`pip check` — `No broken requirements found`. Установщик сообщил только о доступном
обновлении своего pip; обновление не требовалось. Системные Python/Tesseract не входят
в ZIP и были уже установлены на машине.

Независимый сервер из этой папки запущен на 8002: здоровье OCR `ok`, четыре API
аналитики отвечают, локальные графики и таблицы строятся в браузере.
Реальный OCR включённого примера совпал со всеми прежними полями эталона 1.1.0,
в том числе overlay. Явный CLI-импорт выполнен дважды — осталось 111 страниц.
SQL дал одну NULL-ячейку `raggedness`; `PRAGMA foreign_key_check` вернул пустой список.
Новый независимый процесс прочитал три графика из готовой БД с несуществующими
путями к CSV: повторный импорт для запросов не нужен.

Проверены SHA256 каждого файла из манифеста и соответствие исходникам репозитория.
Повторная сборка байт-в-байт воспроизводима; контрольная сумма самого ZIP — рядом,
в `dist/Yunost-OCR-1.2.0.zip.sha256`. Архив 1.1.0, старые корпусные JSON и русские
веса сохранили прежние хеши. Комплект 1.2.0 не включает большой исследовательский
датасет изображений или весь набор тестов — это отдельный компактный runtime-архив.
