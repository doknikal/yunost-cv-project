# Визуальная оттепель — CV-анализ вёрстки журнала «Юность» (1957–1967)

Итоговый проект по курсу «Программирование для цифровых гуманитарных проектов».
Тип — исследовательский. Объект — графический облик страниц журнала «Юность».
Методы — **классическое компьютерное зрение** (OpenCV/NumPy/SciPy/scikit-learn), без нейросетей.

## Исследовательский результат
Между 1957 и 1967 гг. значимо выросла типографическая «рваность» правого края страниц
(медиана 0.125→0.189; Манна–Уитни p≈7·10⁻⁶; размер эффекта 0.63) и число колонок —
измеримый отпечаток эстрадной поэзии. Иллюстративность при этом не выросла («нулевой» результат).
Это вывод исходного ноутбука для выбранного корпуса, а не всего журнала. Страницы
внутри одного номера зависимы; фото 1962–1965 — выборочная преимущественно поэтическая
подборка. Значимость теста по страницам нельзя трактовать как независимое доказательство
исторической причинности. Исторические расчёты не переписывались.

## Лендинг: страница журнала → текстовые блоки
**Рабочий комплект приложения:** [START_HERE.md](START_HERE.md).
На macOS: `bash install_mac.command`, затем `bash start_mac.command`.
Установщик использует отдельную `.venv-app`, не удаляет `.venv`, проверяет Tesseract и хеш русских весов.
Для приложения достаточно `requirements-app.txt`; большой `requirements.txt` нужен для исследования.
Архив с весами и примером собирается командой `python3 build_app.py` в `dist/`.

Загружаете фото или скан страницы — сервис распознаёт **весь найденный текст**:
прозу, стихи, заголовки, подписи и короткие фрагменты, без жанрового отбора.
Физические строки, переносы и приблизительные отступы сохраняются; проза тоже выводится построчно.
Загрузки удаляются после обработки; большие файлы могут временно записываться на диск.
OCR настроен на русский язык.

**Установка.** Кроме `pip install -r requirements.txt` нужен сам OCR-движок Tesseract с русским языком:
```bash
brew install tesseract tesseract-lang            # macOS
sudo apt install tesseract-ocr tesseract-ocr-rus # Ubuntu/Debian
# Windows: установщик UB-Mannheim, при установке отметить Russian; tesseract.exe добавить в PATH
```
**Запуск.**
```bash
uvicorn server:app --reload     # лендинг: http://127.0.0.1:8000/   API-документация: /docs
pytest tests/                   # тесты
```
Для воспроизведения сравнения выбран **Tesseract 5 + русские веса `tessdata_fast`**:
```bash
mkdir -p .venv/tessdata/fast
curl -L https://raw.githubusercontent.com/tesseract-ocr/tessdata_fast/main/rus.traineddata \
  -o .venv/tessdata/fast/rus.traineddata
export TESSDATA_PREFIX="$PWD/.venv/tessdata/fast"
uvicorn server:app --reload
```
Движок и веса бесплатные, работают локально на CPU; платные API не используются.

**API.** `POST /api/ocr` (поле `file`: JPG/PNG/HEIC до 25 МБ) → JSON: `mode: "all_text"`,
`text`, `text_blocks` (число), `blocks` (принятый текст в порядке чтения), `all_blocks`
(включая сомнительные знаки), `page_size`, `overlay` (PNG в base64).
Каждый блок содержит координаты, физические строки `line_boxes`, слова `words`, текст,
внутреннюю уверенность OCR и источник `page`/`sparse`. Координаты соответствуют странице высотой
до 2000 px и шириной до 4000 px; картинка overlay уменьшена вдвое.
Поле `words[].original_text` хранит исходное чтение заменённого слова (иначе пустая строка),
`refined_words` — число таких слов. Поля `prose_blocks`/`is_prose` удалены из API.
`GET /api/health` проверяет
не только наличие Tesseract, но и доступность русского языка: `ok`, `russian_missing`, `tesseract_missing`
или `tesseract_error`.
Поле `first_block` — первый принятый блок или `null`. Оно добавлено в 1.2.0;
остальные поля OCR сохраняют прежний формат.

### SQLite и интерактивная аналитика

На странице **http://127.0.0.1:8000/analytics** доступны:

1. Гистограмма: выбор одного из девяти признаков и числа интервалов (2–60).
2. Динамика по годам: признак и среднее/медиана; сканы и фото — отдельные серии.
3. Диаграмма рассеяния: выбор признаков для осей X и Y.

Общие фильтры — начальный/конечный год и источник. Под графиками — числовые таблицы.
Первая загрузка импортирует `data/manifest.csv` и `data/features.csv` в
`data/corpus.sqlite3` (111 страниц, 15 номеров). Затем все выборки читаются SQL-запросами;
CSV остаются только источниками импорта. SQLite входит в стандартную библиотеку Python.
Один пропуск `raggedness` хранится как NULL, не как ноль.
OCR-загрузки и исходные машинные пути из CSV в базу **не записываются**.

Повторяемый импорт/обновление без дубликатов:

```bash
.venv-app/bin/python import_corpus.py
.venv-app/bin/python import_corpus.py --database data/demo.sqlite3
```

Путь приложения можно изменить переменной `YUNOST_DB_PATH` перед запуском сервера.
Импорт транзакционный, обновляет совпадающие страницы, добавляет новые и не удаляет
отсутствующие в CSV. Чужая база и неизвестная версия схемы не перезаписываются.
Для создания базы нужны права записи в её каталог. Ошибка инициализации аналитики
даёт 503 и не отключает OCR.

API (`GET`):
- `/api/analytics/options` — объём корпуса, годы, источники, признаки.
- `/api/analytics/histogram?metric=raggedness&bins=12`.
- `/api/analytics/trend?metric=raggedness&aggregation=median`.
- `/api/analytics/scatter?x_metric=n_columns&y_metric=raggedness`.

Последние три принимают `year_min`, `year_max`, `source=all|scan|photo` и возвращают
`selected_pages`, `used_pages`, `missing_pages`. Некорректные параметры — 422;
пустая выборка — 200 с пустыми данными. Метрики — геометрические признаки, не качество OCR.
Графики строит plotly в Python (`yunost/charts.py`, как в лекции 4 курса); ответы API содержат поле `figure`.
plotly.js сервер отдаёт локально из пакета `plotly` (`/vendor/plotly.min.js`): внешний CDN не нужен.

**Как это устроено** (пакет `yunost/`):
1. `TextExtractor` (`text.py`) нормализует изображение до 2000 px по высоте / 4000 px по ширине,
   учитывает EXIF, кладёт прозрачность на белый фон и выравнивает освещение.
2. `TesseractEngine.read_layout()` выполняет разметку страницы (`PSM 3`): блоки, строки, слова, координаты.
   Увеличение 1.5× старого блочного OCR здесь не используется: на проверенной «лесенке» оно смешивало колонки.
3. Дополнительный поиск разреженного текста (`PSM 11`) возвращает пропущенные заголовки и короткие строки.
   Новые слова проверяются по координатам, чтобы не дублировать основной проход. Изолированный фрагмент
   перечитывается с полями (`PSM 6`), что помогает крупной начальной букве заголовка.
4. `layout.py` упорядочивает разделы и колонки по свободным промежуткам; сохраняет физические строки,
   дефисы и приближённые отступы в моноширинном тексте. Склейка строк прозы не применяется к стихам.
5. Низкоуверенные OCR-артефакты остаются в диагностике; нет ограничений на число строк,
   заглавные буквы, ровность края, кириллицу или «словесность». Одна буква/цифра тоже может быть текстом.
6. До 12 неуверенных блоков перечитываются отдельно при 1.5× (`refinement.py`).
   Принимаются только небольшие более уверенные замены слов с взаимно-однозначной геометрией,
   подтверждённые отдельным чтением слова (до 24 проверок). Строки, пунктуация, координаты
   и число слов не меняются. Исходное чтение остаётся в API.

Защита работы: одна OCR-задача одновременно (иначе 429), 30 секунд на вызов Tesseract,
90 секунд OCR на страницу (иначе 504), ограничения размера файла/изображения, защита от
устаревшего ответа в интерфейсе. Без EXIF боковой поворот нужно исправлять вручную.
Это локальное приложение, не защищённый публичный сервис.

`ProseExtractor`, `BlockDetector` и их старые тесты сохранены **только для совместимости и исторических
экспериментов**. Сервер их не использует. Для другого движка в новом режиме нужен метод `read_layout()`
с блоками `LayoutBlock` и словами `LayoutWord`; прежний `read_lines()` относится к старому конвейеру.

**Проверка и ограничения нового режима:** [ALL_TEXT.md](docs/ocr_evaluation/ALL_TEXT.md).
Сложные фото, иллюстрации, крупные декоративные буквы и вёрстка могут вызывать ошибки, пропуски,
ложный текст и нарушение порядка. Число блоков не измеряет полноту. Нужна сверка с оригиналом.
Исследовательский `cvpipe.py` и результаты ноутбука не изменялись.
Историческое сравнение пяти OCR — [REPORT.md](docs/ocr_evaluation/REPORT.md),
старое восстановление **только прозы** — [COMPLETENESS.md](docs/ocr_evaluation/COMPLETENESS.md).
Их показатели 26/26 и CER отдельных фрагментов не оценивают новый режим всего текста.
