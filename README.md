# Визуальная оттепель: компьютерное зрение и OCR для журнала «Юность» (1957–1967)

Итоговый проект по курсу «Программирование для цифровых гуманитарных проектов».
Приложение делает две вещи: распознает текст на фото или скане страницы и показывает
статистику верстки 111 страниц журнала. Работает локально, без нейросетей и платных API.
Запуск: `bash install_mac.command`, затем `bash start_mac.command`. Подробности в [START_HERE.md](START_HERE.md).

Адреса приложения после запуска:
- `/` — OCR страницы;
- `/analytics` — три графика с параметрами;
- `/docs` — документация API.

## Исследовательский результат

С 1957 по 1967 год «рваность» правого края страниц выросла: медиана 0.125 → 0.189,
тест Манна–Уитни p ≈ 7·10⁻⁶, размер эффекта 0.63. Выросло и число колонок. Иллюстративность не выросла.

Вывод относится к выбранному корпусу, а не ко всему журналу. Страницы одного номера зависят друг от друга.
Фото 1962–1965 — подборка в основном стихотворных страниц. Значимость теста нельзя читать как доказательство
исторической причины. Исторические расчеты не пересчитывались.

В версии 1.3.0 аудит показал, что исходная метрика чувствительна к рамкам, коротким строкам, наклону и
ошибкам в колонках. Старые числа не доказывают ни точность измерения края, ни жанр страницы.
Новая диагностика и ее проверка описаны в [EDGE_METHOD.md](EDGE_METHOD.md). Старые значения сохранены.

## Датасет

111 страниц, 15 номеров «Юности»: 1957, 1962, 1963, 1965, 1967. Сканов 75 (PNG), фотографий 36 (HEIC).
Нормализованные страницы лежат в `data/norm/`, примеры для OCR — в `1967-12/`.

## OCR: страница журнала → текстовые блоки

Загрузите фото или скан страницы, сервис распознает весь найденный текст: прозу, стихи, заголовки,
подписи, короткие фрагменты. Жанровый отбор не применяется. Физические строки, переносы и приблизительные
отступы сохраняются, проза тоже выводится построчно. Язык распознавания — русский.
Загрузки удаляются после обработки, большие файлы могут временно записываться на диск.

### Установка и запуск

Нужны Python 3.9–3.12 и Tesseract 5 с русским языком.

```bash
brew install tesseract tesseract-lang            # macOS
sudo apt install tesseract-ocr tesseract-ocr-rus # Ubuntu/Debian
# Windows: установщик UB-Mannheim, отметить Russian, добавить tesseract.exe в PATH
```

На macOS проще так: `bash install_mac.command`, затем `bash start_mac.command`.
Установщик создает отдельное окружение `.venv-app`, проверяет Tesseract и хеш русских весов `tessdata_fast`.
Для приложения хватает `requirements-app.txt`. Большой `requirements.txt` нужен только для исследования.
Архив с весами и примером собирает `python3 build_app.py` в папке `dist/`.

Запуск вручную и тесты:

```bash
uvicorn server:app --reload     # http://127.0.0.1:8000/, документация API: /docs
pytest tests/
```

### API

`POST /api/ocr` принимает поле `file` (JPG, PNG или HEIC до 25 МБ) и возвращает JSON:

- `mode: "all_text"`, `text`, `text_blocks` (число блоков);
- `blocks` — принятый текст в порядке чтения, `all_blocks` — то же вместе с сомнительными фрагментами;
- `first_block` — первый принятый блок или `null` (с версии 1.2.0);
- `page_size`, `overlay` (PNG в base64, уменьшен вдвое);
- `edge_analysis` (с версии 1.3.0) — физические строки, правые края, разброс и предупреждения по принятым блокам.

Блок содержит координаты, физические строки `line_boxes`, слова `words`, текст, внутреннюю уверенность OCR
и источник `page` или `sparse`. Координаты даны для страницы высотой до 2000 px и шириной до 4000 px.
`words[].original_text` хранит исходное чтение замененного слова, иначе пустую строку; `refined_words` считает такие слова.
Поля `prose_blocks` и `is_prose` удалены.

`GET /api/health` проверяет Tesseract и русский язык. Ответ: `ok`, `russian_missing`, `tesseract_missing` или `tesseract_error`.

В интерфейсе можно включить слой фиолетовых точек: это правые края строк. Значения нормированы на ширину
OCR-блока с полями, в SQLite не попадают и не влияют на принятие текста.

Ошибки: 400 — нет изображения, 413 — слишком большой файл, 429 — идет другая OCR-задача, 504 — тайм-аут, 500 — сбой движка.

### Как это устроено (пакет `yunost/`)

1. `TextExtractor` (`text.py`) приводит изображение к высоте 2000 px и ширине до 4000 px, учитывает EXIF,
   кладет прозрачность на белый фон и выравнивает освещение.
2. `TesseractEngine.read_layout()` размечает страницу (`PSM 3`): блоки, строки, слова, координаты.
   Увеличение 1.5× здесь не применяется: на проверенной «лесенке» оно смешивало колонки.
3. Поиск разреженного текста (`PSM 11`) возвращает пропущенные заголовки и короткие строки.
   Новые слова сверяются по координатам с основным проходом. Изолированный фрагмент перечитывается с полями (`PSM 6`):
   это помогает с крупной первой буквой заголовка.
4. `layout.py` упорядочивает разделы и колонки по свободным промежуткам, сохраняет физические строки, дефисы и отступы
   в моноширинном тексте. Строки прозы не склеиваются, как и строки стихов.
5. Неуверенные артефакты OCR остаются в диагностике. Ограничений по числу строк, заглавным буквам, ровности края
   и кириллице нет: одна буква или цифра тоже может быть текстом.
6. До 12 неуверенных блоков `refinement.py` перечитывает отдельно при увеличении 1.5×.
   Принимается только небольшая замена слова с совпадающей геометрией, подтвержденная отдельным чтением слова
   (до 24 проверок). Строки, пунктуация, координаты и число слов не меняются.

Ограничения: одна OCR-задача за раз, 30 секунд на вызов Tesseract, 90 секунд на страницу, лимиты размера файла и изображения.
Страницу, повернутую боком без EXIF, нужно повернуть вручную. Приложение локальное и не рассчитано на публикацию в интернете.

`ProseExtractor`, `BlockDetector` и их тесты оставлены для совместимости со старыми экспериментами. Сервер их не использует.
Для другого движка нужен метод `read_layout()` с блоками `LayoutBlock` и словами `LayoutWord`; `read_lines()` относится к старому конвейеру.

Сложные фото, иллюстрации, крупные декоративные буквы и верстка дают ошибки, пропуски, лишний текст и сбои порядка.
Число блоков не измеряет полноту, результат нужно сверять с оригиналом. Проверка режима: [ALL_TEXT.md](docs/ocr_evaluation/ALL_TEXT.md).
Старые сравнения: пять OCR-движков — [REPORT.md](docs/ocr_evaluation/REPORT.md), восстановление только прозы —
[COMPLETENESS.md](docs/ocr_evaluation/COMPLETENESS.md). Их показатели (26/26, CER отдельных фрагментов) к новому режиму не относятся.
В `cvpipe.py` есть метод `method='components-v2'`; вызов по умолчанию остался прежним (`legacy`).

## SQLite и аналитика

Страница **http://127.0.0.1:8000/analytics** содержит три графика:

1. Гистограмма: один из девяти признаков, от 2 до 60 интервалов.
2. Динамика по годам: признак и среднее или медиана; сканы и фото в отдельных сериях.
3. Рассеяние: признаки для осей X и Y.

Общие фильтры: начальный и конечный год, источник. Под графиками есть таблицы.

При первом открытии `data/manifest.csv` и `data/features.csv` импортируются в `data/corpus.sqlite3`
(111 страниц, 15 номеров). Дальше все выборки идут SQL-запросами, CSV остаются только источником импорта.
Единственный пропуск `raggedness` хранится как NULL, не как ноль.
OCR-загрузки и пути с исходного компьютера в базу не записываются.

Импорт можно повторять: дубликатов он не создает.

```bash
.venv-app/bin/python import_corpus.py
.venv-app/bin/python import_corpus.py --database data/demo.sqlite3
```

Другой путь к базе задает переменная `YUNOST_DB_PATH` (перед запуском сервера).
Импорт идет одной транзакцией: обновляет совпавшие страницы, добавляет новые, не удаляет отсутствующие в CSV.
Чужая база и неизвестная версия схемы не перезаписываются. Каталогу базы нужны права на запись.
Ошибка аналитики возвращает 503, OCR продолжает работать.

API (`GET`):
- `/api/analytics/options` — объем корпуса, годы, источники, признаки;
- `/api/analytics/histogram?metric=raggedness&bins=12`;
- `/api/analytics/trend?metric=raggedness&aggregation=median`;
- `/api/analytics/scatter?x_metric=n_columns&y_metric=raggedness`.

Три последних принимают `year_min`, `year_max`, `source=all|scan|photo` и возвращают `selected_pages`, `used_pages`, `missing_pages`.
Неверные параметры дают 422, пустая выборка — 200 с пустыми данными. Метрики описывают геометрию страницы, а не качество OCR.
Chart.js 4.4.8 лежит в репозитории (лицензия MIT), внешний CDN не нужен.
