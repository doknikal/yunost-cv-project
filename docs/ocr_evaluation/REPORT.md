> а не полноту. Последующая проверка обнаружила пропущенные окончания и реплики.

## Выбор бесплатного движка

Для этого проекта выбран **Tesseract 5.5.3 + русский `tessdata_fast/rus.traineddata`**.
Работает локально на CPU, без платного API и отправки страниц внешним сервисам.
Код Tesseract и выбранные веса распространяются под Apache-2.0.

Сравнивались пять конфигураций на одинаковых шести визуально сверенных фрагментах:
**1 983 символа** после нормализации пробелов и склеивания переносов слов.
CER — редакционные ошибки / длина эталона; меньше лучше. Регистр и пунктуация учитываются.

| OCR | CER | Время шести фрагментов | Время исходного конвейера на восьми страницах |
|---|---:|---:|---:|
| **Tesseract-fast** | **2,47%** | 1,50 с | 11,28 с |
| Tesseract-best | 2,92% | 3,49 с | 23,80 с |
| EasyOCR 1.7.2, русский/английский | 20,42% | 3,87 с | 31,52 с |
| Paddle PP-OCRv5 Cyrillic через RapidOCR/ONNX | 21,99% | 11,37 с | 26,62 с |
| Paddle PP-OCRv5 ESLAV через RapidOCR/ONNX | 24,56% | 6,52 с | 26,03 с |

Это сравнение конкретных интеграций, **не универсальный рейтинг моделей**. Ошибки нейросетевых
вариантов включают детекцию и группировку наклонных строк. Все возможные настройки не перебирались.
Время приблизительное: MacBook Pro M1 Pro, 16 ГБ, CPU; инициализация/загрузка весов исключены,
возможна фоновая нагрузка. Восьмистраничные замеры сделаны до улучшений конвейера.

В эталоне исправлено название «Татарской» → **«Тагарской»**, сверенное с изображением.
Исторические JSON не перезаписывались: `corrected_metrics.json` пересчитывает сохраненные
предсказания по исправленному `samples.json`. Для отчета используются именно пересчитанные CER.

## Что было не так с «рваностью»

1. На фото наклонные/изогнутые строки сливались в горизонтальной проекции. Геометрия считала
   строки неправильно и иногда отбрасывала прозу еще до OCR.
2. Длинные строки и «лесенка» в стихах давали ложный ровный край. Проверки только заглавных
   букв было недостаточно.
3. Старые тесты проходили, хотя визуально подтвержденные стихи попадали в результат.

Исследовательский `cvpipe.py` и результаты ноутбука **не менялись**. Исправления относятся к приложению
`yunost/`, а не пересчитывают научные выводы о журнальной верстке.

## Изменения и проверка этапов

- **Кандидаты:** жесткий отбор по ровности маски снят. Для широкого наклонного блока, где проекция
  видит меньше трех строк, выполняется дополнительная проверка после выравнивания маски.
  Так восстановлено вступление «Так сказали мудрецы» на `1965-02_p10.png`.
- **Подготовка:** медианный фильтр 3×3 применяется только при измеримой текстуре фона;
  затем каждый блок осторожно поворачивается в пределах ±6°. Поворот расширяет изображение,
  не обрезая углы. Чистые сканы остаются без сглаживания.
- **OCR:** сохраняются физические строки и их координаты, а не только склеенный текст.
- **Отбор:** совместно учитываются продолжения фраз, переносы слов, независимые наклоны полей,
  заглавные буквы, глубокие отступы и строфические промежутки. Ровный край сам по себе недостаточен.
- **Сборка:** перекрывающиеся повторные чтения одного абзаца исключаются по геометрии **и**
  совпадению последовательности слов. Исправлен повтор вступления на `1957-04_p08.png`.
- **Диагностика:** номера рамок совпадают с номерами блоков на сайте; доступны причины исключения,
  сырые строки OCR, признаки, угол и факт шумоподавления. Исключенный текст не входит в итоговый `.txt`.
- **API:** health-проверка действительно проверяет русский язык; некорректные, слишком маленькие
  и экстремально узкие изображения отклоняются.

Промежуточные изображения подготовки и итоговые рамки просмотрены вместе с прочитанным текстом.
При сверке также обнаружены и исправлены ошибочные сопоставления названий/областей в первоначальной
агентской разметке; используется пересмотренная версия 2, а не первоначальные контактные листы.

## Проверка страниц

Исходный и улучшенный варианты обработали все **111 нормализованных страниц** без ошибки выполнения.
Сохранены `tesseract-fast_corpus.json` и `improved_corpus.json` с текстом и решениями по блокам.
Финальная оценка присутствия прозы относится только к **26 выбранным и визуально проверенным страницам**:
18 с прозой, 8 только со стихами. Это регрессионная выборка, не случайная и не отложенная.

| Решение о наличии прозы на странице | До | После |
|---|---:|---:|
| Правильные решения | 17/26 | **26/26** |
| Страницы только со стихами, ошибочно принятые за прозу | 6 | **0** |
| Страницы с полностью пропущенной прозой | 3 | **0** |

Восстановлены вступления на `1957-06_p05.png`, `1957-07_p04.png`, `1965-02_p10.png`.
Финальный прогон 111 страниц занял около 178,5 с. Полный набор тестов: **56 passed** (50,60 с).
Через браузер проверена загрузка смешанной фотографии `1963-12_p07.png`: две прозаические колонки;
фото со стихами `1965-02_p01.png` дает пустой итоговый текст и 15 диагностических блоков.

Визуальные сравнения: [рамки до/после](classification_review.jpg),
[подготовка фрагментов до/после](preprocessing_review.jpg).

Наличие хотя бы одного правильного блока на странице **не означает**, что извлечена вся проза или
что каждый символ распознан верно. `metrics.pages[].regions[].box_coverage` — лишь покрытие
приблизительных прямоугольников рамками, не посимвольная полнота и не точная сегментационная метрика.

## Что остается нерешенным

- **Сильный изгиб страницы не исправлен.** На верхних строках фото `1963-12_p07.png` OCR все еще
  заметно искажает слова. Маленькие проверенные фрагменты ниже читаются лучше всей изогнутой колонки.
- Короткие прозаические окончания и подписи могут пропускаться: это видно, например, в верхней
  правой части `1967-10_p03.png`. Одно верное решение на странице не скрывает этих пропусков.
- Декоративные/жирные шрифты путают буквы; даже восстановленное вступление `1965-02_p10.png`
  требует вычитки. Неправильные символы не заменяются выдуманным «исправленным» текстом.
- Необычные стихи, проза без переносов и короткие диалоги остаются трудными случаями эвристик.
- Остальные 85 страниц не имеют полной визуальной разметки. Нулевой результат на них не доказывает
  отсутствие прозы. Посимвольного эталона всего корпуса нет.

## Воспроизведение

Из корня проекта, после установки зависимостей и русских весов по README:

```bash
export TESSDATA_PREFIX="$PWD/.venv/tessdata/fast"
.venv/bin/python -m pytest tests/ -q
.venv/bin/python docs/ocr_evaluation/evaluate.py --corpus
uvicorn server:app --host 127.0.0.1 --port 8000
```

SHA256 использованных русских fast-весов:
`e16e5e036cce1d9ec2b00063cf8b54472625b9e14d893a169e2b0dedeb4df225`.

`evaluate.py` сохраняет хеши исходного кода/эталона, пересчитанные сравнения моделей,
тексты всех страниц и рамки в `.venv/evaluation/final_overlays/`.
Для повторения дополнительных OCR: `pip install rapidocr==3.10.0 onnxruntime==1.19.2 easyocr==1.7.2`,
затем `benchmark.py --engine <имя>`; Tesseract-best требует отдельного `rus.traineddata` из `tessdata_best`.
Первый запуск нейросетевых вариантов скачивает веса. `benchmark.py` использует текущий конвейер
и перезаписывает одноименный JSON: для нового сравнения сохраняйте исторические результаты отдельно.

Ссылки на бесплатные компоненты: [Tesseract](https://github.com/tesseract-ocr/tesseract),
[русские fast-веса](https://github.com/tesseract-ocr/tessdata_fast),
[PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR), [RapidOCR](https://github.com/RapidAI/RapidOCR),
[EasyOCR](https://github.com/JaidedAI/EasyOCR).
