# Полнота извлечения: исправление пропусков

> Историческая проверка старого режима **только прозы**. Приложение теперь извлекает
> текст без жанрового отбора: [ALL_TEXT.md](ALL_TEXT.md). Снимки этого отчета сохранены.

Предыдущие **26/26** означали только правильное определение наличия прозы на странице.
Это была недостаточная проверка для задачи извлечения **всей** прозы. Она не обнаруживала
потерянные окончания, короткие реплики и фрагменты между большими абзацами.

## Что найдено по оригиналам

Четыре страницы открыты по отдельности, пропущенные участки дополнительно увеличены и
транскрибированы в [`completeness_labels.json`](completeness_labels.json). В файле сохранены
координаты, хеши изображений/старого результата и причины пропуска.

На `1967-10_p03.png` отсутствовали пять фрагментов:

- «Вот что сказала Кымытваль:»;
- две строки внизу левой колонки «...Мы шли по улице...»;
- продолжение этого абзаца вверху правой колонки;
- «Потом, улыбнувшись, она закончила...» и следующая реплика;
- «Она написала эти стихи...» и вводные строки о переводе.

На `1957-12_p06.png` отсутствовали два фрагмента окончания рассказа: продолжение диалога
«Вы что-то сказали, дорогой?..» и заключительные короткие предложения «Он бредит...».
Последние ошибочно принимались за стихи из-за заглавных букв и коротких строк.

На контрольных `1957-12_p03.png` и `1957-10_p04.png` дополнительных отсутствующих прозаических
абзацев не обнаружено. Однако декоративная начальная «В» в слове «Весною» на второй странице
пропущена самим OCR; она находится внутри исходного прочитанного прямоугольника.

## Изменение границ колонок

Добавлен `yunost/recovery.py`: после первого OCR-прохода подтвержденная проза служит
опорой для второго прохода **по всей ширине колонки**, а не по отдельным связным компонентам.

- Близкие физические строки проверяются выше и ниже найденного абзаца. Так возвращаются
  короткие окончания и строки, разделенные на несколько узких компонентов.
- Учитываются масштаб шрифта, расстояния между строками и положение относительно поля.
  Редкие шумовые пиксели не считаются левым краем строки.
- Большие пробелы, иной отступ, крупный заголовок и отдельно отвергнутый длинный стихотворный
  блок останавливают расширение. Без подтвержденной прозы расширение не запускается.
- Расширенный блок читается заново и проверяется. Для пограничного случая с короткими
  диалогами требуется сохранение ≥90% последовательности слов настоящего опорного абзаца
  и положительные признаки продолжения прозы. Общий порог для коротких отдельных блоков не снижен.
- Перекрывающиеся чтения удаляются из итогового текста, но остаются в диагностике.
  Принятые блоки упорядочиваются отдельно от отвергнутых широких рамок: последние больше
  не меняют порядок левой и правой прозаических колонок.

## Проверка результата

**Все семь обнаруженных отсутствующих фрагментов теперь представлены в итоговом тексте.**
Это целевые регрессионные примеры, использованные при разработке, а не оценка полноты всего корпуса.

| Фрагмент | Был в итоговом тексте раньше | После | Ошибки лучшего совпадающего фрагмента¹ |
|---|---|---|---:|
| Кымытваль: вводная строка | Нет | Да | 0% |
| Прогулка: конец левой колонки | Нет | Да | 1,1% |
| Прогулка: начало правой колонки | Нет | Да | 1,5% |
| Реплика о переводе стихов | Нет | Да | 0% |
| Строки перед стихотворением | Нет | Да | 0% |
| Продолжение диалога Игоря | Нет | Да | 0% |
| Короткие заключительные предложения | Нет | Да | 3,4% |

¹ Редакционное расстояние к лучшей подстроке полного результата относительно краткого
визуально сверенного эталона; регистр и пробелы нормализованы. Это **не CER страницы**,
не строгая полнота слов и не доказательство отсутствия других пропусков.
Оценка покрытий прямоугольников также не равна полноте букв: в эталонных областях есть поля.

Повторно обработаны **111 страниц** без сбоев. Текст изменился только на двух указанных
страницах: на остальных 109 он совпал с предыдущим сохраненным результатом.
Проверка наличия прозы на 26 размеченных страницах остается 26/26;
полный набор тестов — **63 passed**. Тесты проверяют ранее пропущенные фразы, сохранение
основных абзацев, порядок колонок и исключение стихов, а не только число блоков.

Через браузер загружена `1967-10_p03.png`: все четыре проверенных вводных/заключительных
якоря присутствуют в поле результата, стихотворный текст исключен. В интерфейсе видны
повторный проход по колонке и предупреждение, что число блоков не измеряет полноту.
Через браузер также проверена `1957-12_p06.png`: заключительный диалог появился,
порядок колонок правильный, нижнее стихотворение исключено.

Визуальное сравнение: [до / после](completeness_review.jpg).
Старый снимок `improved_corpus.json` **не перезаписан**;
новый результат — [`completeness_corpus.json`](completeness_corpus.json).

## Оставшиеся ограничения

- Восстановлены перечисленные пропуски, но **полная проза всего корпуса не размечена**.
  Не следует считать остальные страницы гарантированно полными.
- Отдельный короткий абзац вдали от подтвержденной прозы все еще может потеряться.
- Сильная кривизна строк на `1963-12_p07.png` и декоративные инициалы остаются отдельными
  проблемами OCR. Изменение прямоугольного края колонки само по себе их не исправляет.
- В восстановленном тексте есть опечатки («холоднес», «ве привыкла», «оч верил»).
  Они не заменяются автоматически на предполагаемый литературный оригинал.
- Эвристики соседства могут ошибиться на новой верстке; требуется дальнейшая визуальная проверка.

Отдельно проверен прототип коррекции кривизны верхних строк фото `1963-12_p07.png`:
вертикальные смещения по компонентам букв помогают правому краю, но результат зависит
от выбора фрагмента и не устраняет ошибки букв. Построчный поворот не оказался стабильным.
Прототип **не включен безусловно** в приложение и не участвует в заявленных результатах
семи восстановленных пропусков. Локальные материалы: `.venv/evaluation/curvature/README.md`.

## Воспроизведение

```bash
export TESSDATA_PREFIX="$PWD/.venv/tessdata/fast"
.venv/bin/python -m pytest tests/ -q
.venv/bin/python docs/ocr_evaluation/evaluate.py --corpus --output-prefix completeness
```

Из корня проекта. Результаты сравнения семи пропусков и инициала находятся в полях
`completeness` и `previous_completeness`, хеши производственного кода — в `code_sha256`.
Рамки текущего прогона: `.venv/evaluation/completeness_overlays/`.
